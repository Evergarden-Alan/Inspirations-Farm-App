# Inspirations Farm — 未来优化规划

> 文档版本：v1.0  
> 创建时间：2026-07-27  
> 基于版本：v1.0.1

本文档记录项目未来迭代的优化方向，按类别组织。

---

## 🎨 UI/UX 优化

### 视觉交互
- **暗色模式支持** — 添加深色主题切换，本地持久化偏好设置
- **动画优化** — 使用 Framer Motion 增强卡片展开/收起、任务完成、列表重排等交互的流畅度
- **手势操作** — 卡片滑动删除/归档（移动端），长按快捷菜单
- **虚拟滚动** — 大量灵感/任务时的性能优化（react-window / @tanstack/react-virtual）
- **加载骨架屏细化** — 当前骨架屏较粗糙，可针对卡片结构设计更精确的占位

### 响应式体验
- **横屏适配优化** — 移动设备横屏时的布局调整
- **Tablet 专属布局** — iPad 等中等屏幕的三栏布局探索
- **键盘快捷键** — 桌面端快速导航、快速添加任务/灵感（如 `Ctrl+K` 全局搜索）

### 信息密度
- **可折叠的日程区块** — 「近期计划」「当日日程」「本日总结」可独立折叠，减少滚动
- **紧凑视图模式** — 列表/卡片密度切换（宽松/紧凑）
- **优先级颜色系统优化** — p0-p3 配色在深色模式下的对比度调整

## ⚙️ 功能增强

### 灵感管理
- **全文搜索** — 搜索灵感标题、内容、标签（客户端或服务端实现）
- **批量操作** — 多选灵感批量归档/删除/修改标签
- **灵感关联** — 灵感之间的双向链接（类似 Obsidian `[[wikilink]]`）
- **灵感模板** — 预设格式模板（如读书笔记、技术方案、日常思考）
- **附件支持** — 图片/文件上传到 GitHub 仓库，在灵感中引用
- **灵感分类/文件夹** — 按项目、主题组织灵感（对应 GitHub 子目录）

### 任务管理
- **任务优先级** — 为 Daily 任务添加优先级标记
- **任务估时** — 番茄钟集成或简单时长估算
- **重复任务** — 每日/每周重复任务自动生成
- **任务视图切换** — 看板视图（Kanban）、时间轴视图
- **任务统计** — 完成率趋势图、延期任务热力图

### 数据同步
- **冲突解决 UI** — 当前 409 自动重试，可显示冲突内容让用户手动选择
- **离线编辑队列** — PWA 离线时记录操作队列，联网后同步
- **多设备同步状态指示** — 显示最后同步时间、是否有未推送更改
- **WebSocket 实时同步** — 多设备打开时实时推送更新（需后端服务）

### 内容增强
- **代码高亮** — Markdown 代码块语法高亮（rehype-prism / shiki）
- **Mermaid 图表** — 支持流程图、时序图渲染
- **Excalidraw 集成** — 手绘图表嵌入
- **音频/视频嵌入** — 支持 YouTube/Bilibili 链接预览

## 🔧 技术架构

### 性能优化
- **React Server Components 深化** — 更多组件迁移到 RSC，减少客户端 bundle
- **增量静态生成（ISR）** — 灵感列表页面的智能缓存策略
- **图片优化** — next/image 自动优化上传的图片
- **代码分割** — 按路由/功能动态导入（Markdown 编辑器、图表库等）
- **Service Worker 缓存策略优化** — 更细粒度的缓存控制（stale-while-revalidate）

### 数据层
- **本地数据库** — IndexedDB 存储离线数据，减少 GitHub API 调用
- **数据预加载** — 预测用户行为，提前加载可能访问的数据
- **乐观更新增强** — 更多操作采用乐观更新，失败时回滚 UI
- **GraphQL 探索** — 使用 GitHub GraphQL API 减少请求次数

### 可靠性
- **客户端 409 重试** — `PUT /api/daily` 的并发编辑冲突客户端自动重试（DEVLOG 已提及）
- **操作撤销（Undo）** — 删除/归档操作的撤销机制（5s 缓冲期）
- **数据备份** — 定期导出到本地/云存储（JSON/ZIP）
- **版本历史** — 利用 Git commits 展示灵感/日志的修改历史

### 测试覆盖
- **单元测试** — 核心逻辑（markdown-utils, cascade, rollover）的 Jest/Vitest 测试
- **集成测试** — API routes 的端到端测试
- **E2E 测试** — Playwright 覆盖关键用户流程
- **类型安全增强** — 更严格的 TypeScript 配置（strict mode）

## 🚀 部署与运维

### 监控与诊断
- **错误追踪** — Sentry 集成，捕获生产环境异常
- **性能监控** — Web Vitals (LCP/FID/CLS) 上报
- **日志聚合** — 结构化日志，Vercel 日志分析
- **用户行为分析** — 隐私友好的分析工具（Plausible / Umami）

### DevOps
- **CI/CD 增强** — GitHub Actions 自动测试、类型检查、构建
- **预览环境** — PR 自动部署预览版本
- **A/B 测试框架** — 功能开关（feature flags）和灰度发布
- **性能基准测试** — 自动化性能回归检测

### 安全加固
- **内容安全策略（CSP）** — 防止 XSS 攻击的 HTTP 头配置
- **速率限制** — API 端点防暴力破解（如 PIN 尝试次数限制）
- **审计日志** — 记录关键操作（创建/删除/归档）
- **双因素认证** — PIN + TOTP 两步验证

## 🎯 优先级建议

### 高优先级（3 个月内）
1. **暗色模式** — 用户呼声高，实现成本低
2. **全文搜索** — 数据量增长后的刚需
3. **客户端 409 重试** — 已知问题，影响数据一致性
4. **错误追踪（Sentry）** — 尽早建立监控体系

### 中优先级（6 个月内）
1. **虚拟滚动** — 性能瓶颈出现前准备
2. **代码高亮 + Mermaid** — 提升内容表达力
3. **任务优先级** — 与灵感优先级形成完整体系
4. **单元测试覆盖** — 保障重构信心

### 低优先级（探索阶段）
1. **多用户/团队协作** — 需要架构重构，评估需求
2. **WebSocket 实时同步** — 需要独立后端服务
3. **AI 功能** — 成本和隐私考量

## 📝 贡献指南

欢迎社区贡献！实现某个优化方向时：
1. 在 GitHub Issues 中创建对应提案
2. 讨论技术方案和权衡

**原则**：
- 保持简洁性（Simplicity First）
- 移动优先（Mobile First）

- 渐进增强（Progressive Enhancement）
